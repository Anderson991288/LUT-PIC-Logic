承接：M4 s3 交出 13.2 ps 盒的認證窗（AND4／MAJ4／XOR2 單葉 30.5／33／37 ps，每側餘裕 3.75–7 ps）；M3 s3 交出對齊與盒內 41 點的詳細模擬窗（共同窗與扣中點兩種）。

本步要回答：10 Gb/s 的一個 UI（100 ps）被哪些效應依序占去（草稿表 VI）？接收端頻寬改成 5–9 GHz、或位元率提高時，窗還夠 Treq＝23 ps 嗎（草稿 IV-F）？只看一組延遲與看整個延遲盒的認證，結論一樣嗎？

交給下一步：budget_ui.json（三個函數的 UI 分配，類比接收端延伸到盒內最小與認證窗）與 sens.json（頻寬、位元率掃描的一組延遲窗，以及單葉與切細兩種認證窗）。M4 到此結束；M5 的串接與補長度選擇沿用同一套窗的定義與認證條件。

名詞對照：ISI（inter-symbol interference，符號間干擾）＝接收端的記憶讓前後符號的波形混進目前符號的判讀量，使窗變窄；數位接收端＝以雙線性轉換設計的數位二階 Butterworth 濾波器，草稿表 VI 與 IV-F 用它，表 III 與認證用類比濾波器的 FOH 精確離散。

① 問題與範例

考慮一份 100 分鐘的會議時間表：開場與收尾（邊緣與 ISI）占掉一大塊，再扣掉可能的延誤（雜訊、skew），剩下的時間要放進一段固定 23 分鐘的報告（Treq），多出來的才是緩衝。表 VI 只算「某一天」的延誤（一組延遲）；但要保證每天都排得下，得用最壞情況的延誤（整個延遲盒），而且要用能證明的上限（認證窗），不能只用抽查過的那幾天。本步把這兩種算法放在同一張預算表上，再看接收端頻寬與位元率改變時，兩種結論會不會分岔。

學習目標：(1) 依序加入效應，算出三個函數的 UI 預算，並延伸到盒內最小與認證窗；(2) 掃描接收端頻寬 5–9 GHz，看窄頻寬的兩個相反作用（雜訊變小、ISI 變長）；(3) 掃描位元率 10–25 Gb/s，比較「一組延遲」與「整盒認證」能支援的最高位元率。

② 原理與推導

1. 依序扣除的 UI 預算

令 W0 是對齊、不扣護欄的窗（只看判讀方向是否正確），Wn 是對齊、扣時變護欄的窗，Ws 是 x3、x4 晚 13.2 ps 這一組延遲、扣護欄的窗（都用 M3 s3 的共同窗算法，單位 ps）。一個 UI 依序分成：

UI=(UI−W0)⏟邊緣與 ISI+(W0−Wn)⏟雜訊+(Wn−Ws)⏟skew+(Ws−Wctr)⏟盒內其他 skew+(Wctr−Wbox)⏟共同平移+(Wbox−Wcert)⏟認證保守+Treq+(Wcert−Treq)⏟剩餘

Wctr 是 M3 s3 盒內 41 點扣中點的窗（每組延遲先減去所有輸入共同的平移，只剩 skew），Wbox 是同 41 點的共同窗，Wcert 是 M4 s3 的認證窗（情境序列、單葉盒）。共同窗要求同一個取樣時刻服務所有輸入同向的 ±6.6 ps 平移，所以 Wctr − Wbox 是「取樣時刻固定、不跟著共同延遲調整」的代價；認證窗用同一個共同窗定義，也含這一份。草稿表 VI 只到 Ws，剩餘寫成 Ws − Treq。每一項是前後兩次分析的差，次序換了數值會變，不能當成可以任意相加的獨立損失；例如先加 skew 再加雜訊，兩項各自的大小都會不同。

2. 頻寬與位元率的兩個相反作用

接收端 f3dB 變窄時，雜訊等效頻寬 BN＝f3dB·(π/4)/sin(π/4) 跟著變小，護欄 Γ 變小；但脈衝響應 h 變長，前後符號混進來（ISI），判讀量在 UI 內爬升得更慢。位元率提高時，本步讓接收端頻寬（f3dB＝0.7×位元率）、輸入邊緣（全寬 0.3125 UI）與時間格（UI/200）一起縮放，所以以 UI 為單位的波形幾乎不變；但 Treq＝23 ps、skew 13.2 ps 與延遲盒 ±6.6 ps 是物理時間，不跟著縮小，占 UI 的比例越來越大。

UI 預算：數位接收端的 AND4 是邊緣與 ISI 45、雜訊 5、skew 2.5 ps，Ws＝47.5 ps，每側餘裕 12.25 ps；草稿表 VI 為 43／5.5／2 ps、49.5 ps、13.25 ps。三項的分配一致（邊緣與 ISI 占最多、雜訊與 skew 各幾 ps），總窗差 2 ps（原因見 ③）。但表 VI 的「每側 12–13 ps」只對一組延遲成立：延伸到整盒後，盒內其他 skew 再占去 5.5 ps、所有輸入同向的共同平移 4.5 ps、認證的保守量 6.5 ps，保證的每側餘裕只剩 3.75 ps，約為表 VI 的 30%。草稿在表 VI 之後也寫明「保守保證是認證窗 31.5 ps」，本步把這句話放進預算表。

接收端頻寬：一組延遲（x3、x4 晚 13.2 ps）的窗在 5–9 GHz 為 AND4 30.0–56.0 ps（草稿 28.5–56.5 ps），三個函數都高於 Treq，與草稿結論相同；頻寬越窄窗越窄，表示這個範圍內 ISI 變長的影響大於雜訊變小。認證窗對頻寬更敏感：單葉時 5 GHz 的 AND4 只剩 8.5 ps、MAJ4 13 ps，6 GHz 的 AND4 剛好 23.0 ps；切細後 6 GHz 的 AND4 有 28 ps，5 GHz 的 AND4 仍只有 17 ps、MAJ4 20.5 ps。XOR2 在 5 GHz 單葉就有 27 ps。原因是窄頻寬讓判讀量在 UI 內爬升得更慢，窗的兩端斜率變小，下界扣掉同樣的一階項與餘項，換算成時間就少更多。所以在本模型下，以 13.2 ps 盒認證時，AND4、MAJ4 在 6 GHz 以上可以認證，5 GHz 用到切細仍不能；認證是充分條件，5 GHz 不能認證不等於一定失敗，要嘛切更細，要嘛承認保證只到 6 GHz。

位元率：只看一組延遲時，AND4、MAJ4 到 15 Gb/s、XOR2 到 20 Gb/s 仍通過，與草稿完全相同。整盒的單葉認證窗在 12.5 Gb/s 已降到 18／19.2／14 ps；每路切 2 份後 12.5 Gb/s 為 24.4／27.2／32.8 ps，三個函數都能認證，15 Gb/s 則是 17.3／19／19 ps，切細也不通過。差別來自固定的物理時間：位元率提高時 UI 變短，±6.6 ps 的延遲盒占 UI 的比例變大，認證的一階項與餘項跟著變大。草稿已寫明位元率掃描「不是最高速率的證明」；本步把它量化：在本模型下以 13.2 ps 盒認證，目前做到 12.5 Gb/s（切細），15 Gb/s 要更細的葉盒或更小的延遲盒才可能認證。

驗收：(a) 數位接收端 AND4 的 UI 預算 45／5／2.5 → 47.5 ps，與草稿表 VI 的 43／5.5／2 → 49.5 ps 相差 2 ps 以內（通過，原因見 ③）；(b) 頻寬掃描的一組延遲窗 30.0–56.0 ps，與草稿 28.5–56.5 ps 一致、全部 ≥ Treq（通過）；(c) 最高位元率 AND4、MAJ4 15、XOR2 20 Gb/s，與草稿相同（通過）；(d) 類比接收端 Ws ≥ Wctr ≥ Wbox ≥ Wcert、切細的認證窗不比單葉窄、每個頻寬與位元率的認證窗都不大於同一組延遲的類比窗（通過）。預算各項加起來等於 UI 是定義上的恆等式，不算驗收。

本步結論：(1) 10 Gb/s 的一個 UI 中，邊緣與 ISI 占最多（AND4、MAJ4 41–45 ps），雜訊護欄 5 ps、一組延遲的 skew 2.5–6 ps；XOR2 例外，margin 小，雜訊護欄占去 31 ps。(2) 一組延遲的預算會高估餘裕：AND4 每側 12.25 ps，整盒保證只剩 3.75 ps；盒內其他 skew、共同平移與認證的保守量合起來占去 15–29 ps，AND4、MAJ4 比雜訊與 skew 加起來還多；其中 AND4 的 4.5 ps 是共同平移，若取樣時刻能跟著共同延遲調整就能省下。(3) 頻寬與位元率的掃描，一組延遲的結論與草稿相同；換成整盒認證後，目前能認證的是頻寬 ≥ 6 GHz、位元率 12.5 Gb/s（切細；單葉只到 10 Gb/s）。認證是充分條件，這是「目前能保證到哪裡」，不是「超過就一定失敗」。論文寫敏感度時要分清楚是一組延遲還是整盒保證，這一點列入 M7 草稿修改清單。(4) 適用範圍：所有「保證」都在本模型下：升餘弦邊緣、固定延遲、相位已校準，雜訊護欄是 Q＝7 的機率性餘量（不是確定的上界）；skew 只取 x3、x4 晚到這一組；數位與類比接收端都是假設的線性介面；雜訊模型同 M3 s3（不含 shot）；位元率掃描讓頻寬與邊緣等比例縮放，是模型掃描，不是元件規格；時脈抖動（jitter）只以取樣端的 8 ps（含在 Treq 內）扣一次，資料端每個位元不同的抖動沒有建模，若之後加入，要與取樣 jitter 分開，避免同一項扣兩次。

⑤ 常見錯誤與自我檢查

  • 把預算各項當成獨立損失：每一項是前後兩次分析的差，換次序會變；不能把別的設計的某一項直接搬來相加。
  • 用一組延遲的餘裕當保證：表 VI 的每側 13 ps 只對 x3、x4 晚 13.2 ps 這一組成立；整盒保證要用認證窗。
  • 把認證不過當成一定失敗：認證是充分條件；單葉不過時先切細葉盒，仍不過才說「目前無法保證」。
  • 以為頻寬越窄雜訊越小就越好：窄頻寬的 ISI 變長，在 5–9 GHz 內窗是隨頻寬變寬的。
  • 位元率掃描時把 Treq、skew 也一起縮放：取樣器需求與延遲是物理時間，不隨位元率縮小。
自我檢查 1：XOR2 的 skew 項為什麼是 0？如果改成 x1、x2 晚 13.2 ps，結果會怎樣？

XOR2 只用 x1、x2，M4 s1 已看到 x3、x4 的 l、Q 都是 0（弱耦合輸入），所以它們晚多少都不影響判讀量，skew 項為 0。若是 x1、x2 之間差 13.2 ps，兩路的轉態錯開，XOR 的干涉在轉態附近會出現錯誤的脈衝，窗會變窄；M4 s3 的整盒認證已包含這種情況，XOR2 盒內 41 點最小 53 ps 比對齊的 66 ps 少 13 ps，就是這個原因；認證窗再少 16 ps，是單葉盒的保守量。

自我檢查 2：位元率 12.5 Gb/s 時一組延遲的 AND4 窗 36 ps，單葉認證窗卻只有 18 ps、切細後 24.4 ps。哪一個可以拿來回答「12.5 Gb/s 能不能用」？

要看問題是什麼。若佈局與發射端保證所有延遲組合都在 13.2 ps 盒內、又要對每一組都能工作，只能用認證窗：單葉 18 ps < 23 ps 還不能下結論，切細後 24.4 ps ≥ 23 ps，在本模型下可以保證。36 ps 只說明 x3、x4 晚 13.2 ps 這一組可以工作；在情境序列、共同窗、本模型下，盒內真正的最小窗介於認證窗與 36 ps 之間。若切細仍不夠，要嘛切得更細，要嘛縮小延遲盒（例如以等長佈局把 skew 壓到更小）。
